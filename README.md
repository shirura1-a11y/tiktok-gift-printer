# Gift Atelier — TikTok LIVE自動印刷プリンター

接続先 **user52107817831310** のTikTok LIVEギフトを受信し、送信者の名前とアイコンを既存の2Dプリンターへ自動送信します。Node.js＋tiktok-live-connector 2.5.0で受信し、ローカルHTTP/SSEでブラウザのenqueuePrint()につなぎます。

配信Canvasは1080×1920・9:16。上25%の黄金額縁、中央30%のプリンター、下45%の写真展示、手動テスト、印刷音、FIFO、額縁履歴保存を維持しています。操作パネルと接続状態は配信枠の外です。TikTokへのコメント送信・ギフト送信・ログイン・OBS設定は実装していません。

リポジトリ: https://github.com/shirura1-a11y/tiktok-gift-printer

## Windows 10でLIVE自動印刷を起動

1. [Node.js公式サイト](https://nodejs.org/)から **Node.js 24 LTS / 64bit** をインストールし、PowerShellを開き直します。
2. GitHubの「Code → Download ZIP」でダウンロード・展開します。
3. PowerShellで展開先を開き、以下を実行。パスは実際の場所に置き換えてください。

```powershell
cd "$HOME\Downloads\tiktok-gift-printer-main"
node --version
npm ci
npm start
```

4. **http://127.0.0.1:8787** をブラウザで **1タブ** 開きます。index.htmlの直接起動は手動テスト専用で、LIVE連動しません。
5. 初回に配信画面または操作パネルをクリックすると、ブラウザの印刷音を有効化できます。音声OFFでも印刷します。
6. 対象アカウントで公開LIVEを開始。パネルに「LIVE接続済み」、コンソールに `[CONNECTED]` が出ることを確認します。
7. 対応ギフトが届くとアイコン画像を読み込み、自動で印刷します。停止はPowerShellで **Ctrl+C**。

npm ciは初回・依存更新時だけ必要です。PowerShellでnpm.ps1が実行ポリシーにより拒否される場合は、ポリシーを変更せず `npm.cmd ci` / `npm.cmd start` を使用できます。

LIVE開始前に起動しても自動再接続します。配信画面のタブを閉じたままでも、受信済みの印刷待ちをローカルに保存します。ブラウザを開くと未完了分を送信します。

## OBSブラウザソース専用モード

Node.jsを起動して、OBSのブラウザソースを次のように設定してください。

- URL: `http://127.0.0.1:8787/?obs=1`
- 幅: **1080**
- 高さ: **1920**

`?obs=1` のときだけ操作パネルを完全に非表示にし、ページ余白・最大幅制限・影・スクロールを取り除きます。配信Canvasをブラウザソースの幅・高さ100%に表示するため、1080×1920設定では配信画面が全体を埋めます。Canvas内部解像度・印刷・額縁・配色・LIVE処理は変更していません。既存URLにクエリーがある場合は `&obs=1` を追加します。

通常の `http://127.0.0.1:8787/` は従来どおり操作パネルを表示します。OBSを含めて複数の表示を開く場合、自動印刷は既存仕様どおり最初の1タブが担当するため、OBSブラウザソースを先に接続してください。操作画面の手動テストはその画面内で印刷されます。

モード判定は初期表示時のURL確認1回とCSSだけです。追加ライブラリ・連続監視・resize処理・追加の描画ループはありません。操作パネルのDOMは印刷処理が参照するため残し、表示を無効にしています。

## ギフトと演出

| ギフト | 自動印刷 | 上部の黄金額縁 |
| --- | --- | --- |
| バラ / Rose | 通常の丸いアイコン・名前入り写真 | 追加しない |
| ローザ / Rosa | 金糸の刺繍・植物模様が入った豪華な金縁写真 | 追加しない |
| 永遠のローザ / Eternal Rosa / Forever Rosa | 金糸入り豪華写真 | 印刷完了後、右端へ追加 |

黄金額縁は最新5枚を保持。古い肖像は左へ約0.8秒でスライドし、枠外に出たら表示・履歴から削除します。肖像履歴はブラウザのlocalStorageに保存・復元します。

**連続ギフトは、確定した連続送信1組につき写真1枚** です。たとえばバラが1→2→3→終了3と届いた場合、数量3のログを1回記録し、写真は1枚印刷します。1個ずつの枚数展開は行いません。

### ギフト判別の設定

live/config.jsonに接続先、ポート、ギフトID・完全一致の名前を設定します。

```json
{
  "username": "user52107817831310",
  "port": 8787,
  "gifts": {
    "rose": { "ids": ["5655"], "names": ["バラ", "Rose"] },
    "roza": { "ids": [], "names": ["ローザ", "Rosa"] },
    "eternal": { "ids": [], "names": ["永遠のローザ", "Eternal Rosa", "Forever Rosa"] }
  }
}
```

IDを優先し、次に名前を完全一致で照合します。ローザ・永遠のローザの数値IDは推測で登録せず、上記の名称で判別します。地域やTikTokの表記が異なる場合、コンソールの `[GIFT]` / `[UNMAPPED_GIFT]` に出た実際のgiftIdを対応するidsに文字列として追加し、Node.jsを再起動してください。未対応ギフトを価格や部分一致で別の演出へ振り分けることはありません。未知のギフトはログと操作パネルに表示します。

一時的な接続先変更は `npm start -- 別のユーザー名` でも可能。優先順位は引数→環境変数TIKTOK_USERNAME→config.jsonです。.envの自動読み込みは行いません。

## テストモード

### TikTokへ接続せず、受信から印刷まで確認

```powershell
npm run demo
```

同じ http://127.0.0.1:8787 を開くと「デモ受信モード」になります。操作パネルの「サーバー経由の受信テスト」の🌹・✨・👑で、模擬ギフトをNode.jsに発生させます。受信→判別→保存キュー→SSE→既存プリンター→完了通知という、本番と同じ経路を通ります。デモアイコンもローカルで配信するため、TikTok・外部画像サービスへ接続しません。

デモ中は実LIVEには接続せず、キュー保存ファイルも本番と別にします。本番モードではデモ受信APIを無効にします。LIVEとデモは同時起動せず、Ctrl+Cで切り替えてください。

### 従来の手動テスト

サンプルユーザーを選び、「ギフト別テスト」の3ボタンまたは「通常テスト印刷」を押します。これらはブラウザ内だけのテストで、LIVE接続の成否に関係なく使えます。index.htmlを直接開いた場合も手動印刷できます。

### ログのみの模擬受信／自動テスト

```powershell
npm run demo:logs
npm test
```

demo:logsはオフラインの模擬受信ログを流して終了します。途中経過・重複通知を含めても確定ログは3行、数量は3+2+1=6です。npm testはNode.js標準テストランナーを使います。

## 自動再接続とエラー表示

TikTok接続とブラウザ接続は別々に復旧します。

- TikTok接続失敗・切断: 約2→4→8→16→32→60秒の待機に最大1秒のランダム分散を加えて再接続。LIVE終了・オフライン判定・回数制限時は最短30秒待ちます。
- 接続試行全体は60秒でタイムアウト。接続回復時にエラー表示と失敗回数をリセットします。
- ブラウザとNode.jsの接続断: EventSourceが自動再接続し、未完了のジョブを再送します。
- 原因と確認手順をコンソールと画面外の操作パネルに表示。認証情報や署名URLのクエリーを詳細ログから除きます。

| エラー | 確認事項 |
| --- | --- |
| UserOffline / オフライン判定 | LIVEを開始し、ブラウザで対象LIVEを視聴できるか確認 |
| Room ID取得失敗 | ユーザー名・配信状態・地域制限・通信。これだけでオフラインとは断定しない |
| ECONNREFUSED / ENOTFOUND / timeout / TLS | ネット接続・DNS・Windowsファイアウォール・プロキシ・PC日時 |
| 401 / 403 | TikTokまたは署名サービスのアクセス制限 |
| 429 / RateLimit | 自動再接続を待つ。手動での即時再起動を繰り返さない |
| EADDRINUSE | 起動済みのNode.jsを止めるかconfig.jsonのportを変更 |
| ERR_MODULE_NOT_FOUND | プロジェクトフォルダーでnpm ci |
| 未設定ギフト | ログのgiftIdをlive/config.jsonに登録して再起動 |
| キュー保存失敗・上限 | ディスク空き容量・書き込み権限・印刷タブを確認 |

コネクターは非公式で、接続署名にライブラリ既定の外部署名サービスを使います。TikTok側の仕様変更・地域制限・サービス障害・利用回数制限によって接続できない場合があります。実接続に失敗したときにデモへ自動切り替えはしません。

参考: [コネクター公式README](https://github.com/zerodytrash/TikTok-Live-Connector)、[ギフトと連続送信の公式ガイド](https://ttlc.docs.isaackogan.com/guides/gifts/)。

## 重複防止と印刷待ちの復旧

1. 連続ギフトの途中通知は加算せず、repeatEnd=1/trueで確定します。
2. messageIdと、ルーム・送信者・受信者・ギフト・groupIdの組で再配送を除外。再接続時も同じ重複判定器を維持します。別の連続送信を同一ギフトとしてまとめません。
3. 初期の過去メッセージ処理は無効にし、接続時の履歴再計上を避けます。
4. 確定通知から安定したジョブIDを作り、未完了キューと完了履歴をNode.js側の `.local/live-jobs.json` に保存。デモは `.local/demo-jobs.json`。ファイルはGit管理・HTTP配信の対象外です。
5. ブラウザは受信済みジョブを重複追加せず、印刷完了後にサーバーへACKします。サーバーはACK後に未完了キューから削除します。ACK前の再読み込みでは未完了分を再送します。
6. ブラウザも完了IDをlocalStorageに保持し、ACKの通信断時に同じジョブを印刷し直すことを防ぎます。複数タブでは1タブだけに印刷ジョブを送り、他は監視専用です。

途中経過を除く受信ログは `[GIFT]`、印刷待ち追加は `[PRINT_QUEUED]`。種別や識別IDが足りず確定できない通知は `[GIFT_UNCONFIRMED]` とcounted:false付きで記録し、自動印刷しません。

上限: 受信重複判定30分・10,000キー、サーバー未完了キュー1,000件、サーバー完了履歴10,000件、ブラウザ完了履歴2,000件。キュー満杯・ディスク保存失敗はエラーとして表示し、そのギフトは自動印刷できません。最終通知が届かない連続送信を推測で確定しません。履歴上限・サイトデータ削除・ディスク破損・印刷完了と保存の間の強制終了など、障害境界をまたぐ完全なexactly-once処理を保証するものではありません。

起動時に保存キューが破損している場合は、履歴を勝手に消さずエラー停止します。保存ファイルを退避・確認してから再起動してください。複数のNode.jsを同じフォルダーで同時実行しないでください。

## 画面・保存データ・負荷

- 内部解像度1080×1920。上480px / 中央576px / 下864pxの構成と9:16を維持し、横スクロールを抑止。
- 写真は約5.6秒で排紙・落下。下部4列×2段へ最新24枚を重ねて保持。
- 「用紙を片づける」は下部写真のみ削除し、黄金額縁履歴は維持。
- 画像の読み込み失敗・3.5秒のタイムアウトでは、名前の先頭文字による代替アイコンで続行。
- 背景・写真・額縁をCanvasにキャッシュ。目標30fps、待機時はrequestAnimationFrame停止。非表示タブではアニメーションと音を停止し、表示復帰時に再開するため、本番中は印刷タブを表示したままにしてください。
- 黄金額縁はlocalStorageのgift-atelier.portrait-hall.v1、完了IDはgift-atelier.completed-live-jobs.v1に保存。
- localStorageはブラウザとURLのオリジン単位。同じブラウザ・同じ127.0.0.1のURLとポートを使ってください。以前のfile://で保存した履歴は、その保存場所に残りますがHTTP側へ自動移行しません。
- 外部アイコンがCanvas書き出しを許可しない場合も印刷は続行。黄金額縁の復元時には名前付き代替アイコンになります。
- 既存enqueuePrint({name,avatar,gift})、getPrintState()は維持。LIVE用eventIdを渡す場合だけ、印刷完了でgiftprint:completeイベントを発火します。

## 検証結果と実接続の制限

制作環境: Linux x86_64 / Node.js v24.22.1。依存インストール・コネクター実インポート成功。

23項目の自動テストで、ギフト3種の判別、連続送信・再配送の重複除外、再接続、保存キュー復元、SSE、単一印刷タブ、ACK、既存プリンターのFIFO・金縁演出・額縁追加、完了ID復元、ローカル手動テストを確認しました。画面ロジックはCanvas/DOMモックです。実プロセスのデモでも、3種類の模擬受信→保存→SSE送信→完了通知を確認しています。

指定アカウントへの実接続試行ではRoom ID取得経路がECONNREFUSED（接続拒否）となり、この環境ではLIVE接続・実際のギフト受信・本番自動印刷の確認には至っていません。対象がオフラインかどうかは、この結果だけでは判定できません。Windows 10実機・実ブラウザの見た目と音声・RAM 4GB実機での30fpsも未確認です。
