# Gift Atelier — 縦型ギフト連動アイコンプリンター

HTML / CSS / JavaScript / Canvasのみで動作する、外部依存なしのローカルデモです。TikTok連携・OBS設定・3D・外部APIは含みません。

## 起動

4ファイルを同じフォルダーに置き、index.html をWindows 10の現行EdgeまたはChromeで開きます。インストール・ビルド・サーバー・ネット接続は不要です。

GitHub: https://github.com/shirura1-a11y/tiktok-gift-printer

「Code → Download ZIP」でダウンロード・展開できます。

## 配信画面

Canvas内部解像度は **1080×1920、9:16**。画面全体を縦型の配信枠に収めています。

| 領域 | 割合 | 内部座標 | 内容 |
| --- | --- | --- | --- |
| 上部 | 25% | y=0〜480 | アンティーク調の黄金額縁5枠 |
| 中央 | 30% | y=480〜1056 | 既存プリンター、排紙、ランプ、ローラー |
| 下部 | 45% | y=1056〜1920 | 印刷写真の展示 |

表示サイズは縦横比を保ってブラウザの表示領域に縮小。横スクロールは発生しない構成です。ボタン・待機数・サンプル選択などの操作パネルは配信枠の外側に置き、広い画面では右側、狭い画面では下側に表示します。狭い画面で下へスクロールしても配信Canvasの9:16は変わりません。

## ギフト別テスト

操作パネルでサンプルユーザーを選択してボタンを押してください。

| ボタン | 写真 | 上部の肖像展示 |
| --- | --- | --- |
| 🌹 バラ | 通常のプロフィール写真 | 追加しない |
| ✨ ローザ | 金糸の刺繍模様・植物模様・金縁付き写真 | 追加しない |
| 👑 永遠のローザ | ローザと同じ金糸入り豪華写真 | 印刷完了後に右端へ追加 |

従来の「通常テスト印刷」も維持しています。こちらはバラと同じ動作です。

- 約5.6秒で排紙・落下を完了。写真は下部の4列×2段の位置へ落ちます。
- 写真は最新24枚まで保持し、8か所に重ねて展示。古い写真から破棄してメモリ増加を抑えます。
- 連続クリックはギフト種類をまたいでFIFO順に処理。待機数は処理中の1件を含みません。
- 「用紙を片づける」は完成写真だけを削除し、黄金額縁の履歴は保持します。
- 「音声 ON / OFF」でWeb Audioによる合成印刷音を切り替えます。初回のボタン操作で音声を有効化。ブラウザが音声を禁止していても印刷は進みます。

### 確認手順

1. バラ、ローザ、永遠のローザを続けて押し、通常→金縁→金縁の順に印刷されることを確認。
2. 上部には永遠のローザだけが追加されることを確認。
3. ユーザーを切り替えながら永遠のローザを6回以上印刷。最新5枚が右端から追加され、古い肖像が左へ約0.8秒でスライドし、枠外で削除されることを確認。
4. 同じブラウザ・同じ場所から開き直し、展示履歴5枚が復元されることを確認。
5. 用紙を片づけても黄金額縁は残ることを確認。

## 展示履歴

localStorageの `gift-atelier.portrait-hall.v1` に、名前と96×96 PNGサムネイルを最大5件保存します。同じユーザーの複数回印刷も1回ごとに追加。以前のバージョンで保存された肖像も引き継ぎます。印刷待ちキューと下部写真は一時保存で、再読み込み時には消えます。

ブラウザのサイトデータ削除で履歴も消えます。別ブラウザ・別オリジンには引き継ぎません。file:// の保存範囲はブラウザ依存なので、同じファイルの場所・同じブラウザで利用してください。

localStorageが禁止・容量不足・破損の場合は保存できない旨を表示し、印刷と画面内展示は継続。復元画像に問題がある場合は代替アイコンを表示します。外部由来の画像にCanvas書き出しの許可がない場合は名前だけを保存し、復元時は代替表示になります。

## 将来のイベント接続口

```js
enqueuePrint({ name: '視聴者さん', avatar: 'data:image/png;base64,...', gift: 'rose' });
enqueuePrint({ name: '豪華写真', gift: 'roza' });
enqueuePrint({ name: '殿堂入り', gift: 'eternal' });
// ギフト省略・未知の値は通常印刷。以前の呼び出し形式も利用可能。
enqueuePrint({ name: 'ゲスト' });
// 読み込み失敗の確認
enqueuePrint({ name: '画像エラー', avatar: 'data:image/png;base64,broken' });
getPrintState();
```

username / avatarUrl はname / avatarの同義フィールド。ユーザーとギフト種類は受付時にコピーします。画像エラー・3.5秒のタイムアウトでは代替アイコンで継続し、後続が追い越さないように処理します。サンプル3種類は埋め込みSVGで、外部通信を行いません。オフライン利用ではdata URLまたはローカル画像を指定してください。

getPrintState() は printing、loading、waiting、completed、retained、exhibited、galleryNames、galleryMoving、storageOK、animating、currentGift、photoGifts、layout を返します。プログラムから印刷を追加しただけでは、ブラウザの音声制限により操作前には無音の場合があります。

## 描画・負荷と検証

- Canvas内部解像度1080×1920、目標30fps。高DPI端末でも内部解像度を増やしません。
- 背景・写真・額縁は小さなCanvasにキャッシュ。
- requestAnimationFrameは印刷・額縁スライド中だけ実行。待機中・画像準備中は連続描画しません。
- 非表示タブでは描画・印刷進行・印刷音を停止し、復帰時に続行します。

制作環境: Linux x86_64、Node.js v24.22.1、Git 2.52.0。

JavaScript構文チェック、Canvas/DOM/localStorageモックによる次の検証を実施しました。

- 9:16と25% / 30% / 45%の領域寸法、回転後の写真が下45%と横幅内に収まる座標。
- ギフト3ボタン、混在ギフトのFIFO、通常写真と豪華写真の分岐、永遠のローザだけの肖像展示。
- 最新5枚の順序・上限、保存・復元、用紙消去による肖像保持。
- 画像失敗、保存禁止、破損履歴からの回復、非表示タブからの再開、待機中RAF停止。

ブラウザ操作用cua_repl.jsが利用できないため、実ブラウザの外観・音声・スクロール実測は未検証です。Windows 10 / RAM 4GB実機でのCPU使用率とフレームレートも未計測で、30fpsは設計目標です。
